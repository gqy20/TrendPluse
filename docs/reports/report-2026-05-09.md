#### `Arize-ai/phoenix`

- **Bedrock Playground crashes with ModuleNotFoundError on every run attempt**（1）：When users attempt to run any Bedrock model in the Prompt Playground, the app immediately crashes with ModuleNotFoundError for 'types_aiobotocore_bedrock_runtime'. The root cause is that two function-local imports of this dev-only package exist outside the TYPE_CHECKING guard in playground_clients.py, while the Dockerfile uses --no-dev, so the package is absent at runtime. This completely blocks the Bedrock playground use case for any self-hosted deployment.
  - [#13106 [BUG]: Bedrock Playground: ModuleNotFoundError: types_aiobotocore_bedrock_runtime](https://github.com/Arize-ai/phoenix/issues/13106)
- **deleteDatasetEvaluators cascades and permanently deletes shared built-in evaluator definitions across all datasets**（1）：The deleteDatasetEvaluators GraphQL mutation is supposed to remove only a single dataset's link to an evaluator. Instead, it deletes the underlying global Evaluator row, which cascades via FK to delete the global BuiltinEvaluator definition and every DatasetEvaluators row pointing to it across all datasets. Deleting a built-in from one dataset permanently removes that built-in from every other dataset that was using it — a silent, irreversible data destruction bug.
  - [#13090 deleteDatasetEvaluators deletes the underlying built-in evaluator, not just the dataset link](https://github.com/Arize-ai/phoenix/issues/13090)
- **deleteEvaluators mutation API returns incorrect evaluator IDs — mis-pairs global IDs and silently truncates duplicates**（1）：The deleteEvaluators GraphQL mutation's response payload produces wrong (gid, rowid) pairings because it zips an unordered set against the original ordered input list. When built-in evaluators are filtered out, the response's evaluatorIds field lists global IDs that were NOT actually deleted. Additionally, duplicate input gids cause the response to be shorter than the input (zip stops at shorter iterable). Clients relying on the response to verify deletion results get silently incorrect data.
  - [#13091 deleteEvaluators returns mis-paired global ids and truncates duplicates](https://github.com/Arize-ai/phoenix/issues/13091)

#### `ErikBjare/gptme`

- **Context auto-expansion causes silent zero-response failures and session timeouts in autonomous/non-interactive mode**（2）：The `include_paths()` function auto-expands path tokens (backtick-wrapped or plain text with `/`) into full file content or directory listings. In autonomous mode, a single prompt referencing ~6 paths can balloon from ~50KB to 465KB. Weak models (grok-4.20, kimi-k2.6, codex:gpt-5.5) silently fail on oversized prompts — returning zero assistant messages, causing session timeouts and arm demotions in Thompson sampling. Observed 14–15% no_response rate on affected models.
  - [#2333 Add GPTME_DISABLE_PATH_INCLUDE env var for non-interactive prompts](https://github.com/gptme/gptme/issues/2333)
  - [#2354 feat(context): add GPTME_DISABLE_PATH_INCLUDE env var to opt out of include_paths() expansion](https://github.com/gptme/gptme/issues/2354)
- **Shell truncation events produce no context-savings ledger entries, obscuring truncation regressions**（1）：When shell command output exceeds truncation thresholds (GPTME_SHELL_TRUNC_PRE_TOKENS + GPTME_SHELL_TRUNC_POST_TOKENS), the output is truncated but the truncation is not recorded in context-savings.jsonl. This occurs because the logdir ContextVar may not propagate in certain async contexts, causing save_large_output / record_context_savings to never fire. 23 truncation events observed in a single autonomous session with zero ledger entries and no tool-outputs/ directory.
  - [#2343 context-savings: shell _shorten_stdout truncation path produces no ledger entries in some workloads](https://github.com/gptme/gptme/issues/2343)
- **Settings modal is unusable on mobile due to layout overflow**（1）：In gptme's webui, the settings modal is almost unusable on mobile because the right-side settings categories menu takes up most of the viewport width, squeezing the actual settings content. The proposed fix is to use a dedicated /settings route instead of a modal.
  - [#2334 Settings modal squished on mobile](https://github.com/gptme/gptme/issues/2334)

# TrendPulse 日报界面设计说明

本文档固化日报页(`src/pages/reports/daily/[date].astro` 及相关组件)的显示层级设计：
页面如何组织、用户按什么顺序阅读、以及支撑这些决定的原则与 token。
改版面前先读本文档；改完后对照末尾的防回归 checklist 自查。

## 1. 设计主线

**每个区块回答一个问题，区块顺序 = 问题优先级。**
用户带着问题来读日报，而不是来浏览版面。页面是对这些问题按优先级排序的回答；
视觉重量(字号/色彩/面积)严格跟随信息价值分配。

## 2. 页面层级总览

| 顺序 | 区块 | 回答的问题 | 视觉手段 |
|---|---|---|---|
| 1 | Hero 大标题 | 今天发生了什么(一句话) | 衬线 `clamp(26px,2.6vw,40px)`；从摘要首句(≤60 字)或首子句(6-40 字)提取，禁止占位词 |
| 2 | 摘要 + 数据带 | 主线是什么？规模多大？可信吗？ | 摘要 3 行 clamp 可展开；统计行(信号/重点/资料/置信)+ 来源分布堆叠条合成一条数据带；来源注脚 12px |
| 3 | 警示横幅 | 有没有要我立刻注意的？ | 全页唯一高饱和色块；仅破坏性变更/无信号时出现 |
| 4 | 今日重点 | 最重要的几件事是什么？ | 1 条主(衬线 `clamp(23px,2.1vw,32px)`)+ 3 条三列并列；标题即链接，分类为行尾色点标签 |
| 5 | 趋势脉络 | 这些事件构成什么结构？ | 新出现/持续升温两列编号列表 |
| 6 | 全部信号 | 我要自己筛、自己翻 | 筛选器 + 表格 + 分页；全页唯一“工具型”区块 |
| 7 | 历史位置 | 今天在历史中处于什么位置？ | 左主文(Δ 引用块 + 对比段，60em 限宽)+ 右 280px 时间线侧栏；侧栏与区块标题同行起笔 |
| 8 | Issue Radar | 用户在抱怨什么？ | 双层：全局观察(定性三列)+ 痛点排行(定量卡片带计数)；并行层用并行层标题 |
| 9 | Release Radar | 哪些版本值得升级？ | 精选卡片(影响度柱图进标题行右侧)+ 全量列表(同仓库批量发版聚合为单行) |
| 10 | 生态活跃度 | 哪些仓库最活跃？ | 榜单表格 |
| 旁路 | 阅读导航 rail + 日期选择器 | 我要直接跳某段/换一期 | 左 148px rail；侧栏日历弹层；服务非线性阅读 |

## 3. 用户观看顺序

倒金字塔主线 + 抽屉式深挖：

1. **1 秒**：大标题拿到结论；
2. **10 秒**：摘要三行 + 数据带，判断今天值不值得深读；
3. **拦截**：警示横幅(如有)拿走最高优先级注意力；
4. **扫读**：四条重点标题——不点进去也能带走四个要点；
5. **分叉**：要结构→趋势脉络；要全量→全部信号；要语境→历史位置；要用户声音→Issue Radar；要版本→Release Radar；要热度→活跃度；
6. **深挖**：任何标题点击开抽屉，覆盖而非跳页，不打断主线。

每一层独立成立：只看标题带走结论，看标题+摘要带走主线，读完全页带走证据。
信息按“浓度”分层，不按数据源分块。

## 4. 设计原则

1. **视觉重量 = 信息价值**。最值钱的内容拿最大字号；元数据(计数/占比)压成数据带；
   不承载信息的元素直接删除而不是缩小苟活(案例：焦点信号 01-04 编号经三轮质疑后删除)。
2. **字号阶梯每档角色唯一**，且层标题必须大于自己的正文；并行层用并行标题。
   (反例已修：全局观察子标题 13px 小于其正文 15px 的倒挂；补“痛点排行”与“全局观察”并行。)
3. **单左基准线 + 三档垂直节奏**。所有内容左缘同线；
   标题→自己内容 16px(紧耦合)、区块→首层 28px(开篇)、层→下一层 48px(分隔，紧耦合的三倍)。
   (反例已修：色点缩进/卡片内边距造成的三条左基准线打架。)
4. **行长控制，但留白必须有归属**。正文限 60em；宽屏空白要么由侧栏承接(历史位置时间线)，
   要么内容多列化(全局观察三列)；页面级 `max-width: 2200px` 封顶防超宽屏表格失控。
5. **交互语言统一**。标题即链接(hover 变蓝 + 下划线、点击进抽屉)全站一致；
   分类永远是小色点 + 短标签钉在首行右侧；方向符号统一为 CSS 细线箭头族。
6. **渐进披露**。摘要 clamp+展开、信号表分页、生成信息 `<details>`、详情进抽屉；
   首屏只放决策所需的最小信息量。
7. **对齐即层级**。侧栏与区块标题同行起笔——对齐关系在替读者标注“谁和谁是一组”。
   标题行内容约定：**长元信息句**(计数覆盖/质量/窗口，如“解析 45/57 个仓库 · 质量分 0.85”
   “本期 566 个发布 · 覆盖 29 个仓库”)推至行尾(`ml-auto`)，不得孤悬为区块尾注；
   **散文描述**(一句话说明区块定位)与**短计数后缀**(27、(3))留在标题旁。

## 5. 设计 token 清单

### 5.1 字号阶梯(日报页)

| 档位 | 字号 | 用途 |
|---|---|---|
| Hero 大标题 | `clamp(26px, 2.6vw, 40px)` 衬线 | ReportIntro headline |
| 区块标题 | 24px(`.tp-section`) | 历史位置 / Issue Radar / Release Radar … |
| 焦点主标题 | `clamp(23px, 2.1vw, 32px)` 衬线 | 今日重点 01 |
| 层标题 | 17px medium | 全局观察 / 痛点排行 |
| 条目标题 | 16px medium | 痛点卡片主题、Release 仓库名(mono) |
| 正文 | 14-16px | 观察条目/卡片摘要 14px；对比段 16px；Δ 引用块 15px |
| 说明 | 13px | 区块标题旁描述、时间线日期 |
| 注脚 | 12px mono/sans | 来源注脚、质量分、计数说明 |
| 微标签 | 11px mono | 分类 kicker、本期/未归档 |

### 5.2 垂直节奏

| 关系 | 间距 |
|---|---|
| 层标题 → 本层内容 | 16px |
| 区块标题 → 首层 | 28px |
| 层 → 下一层 | 48px |
| 三列网格列间距 | 24px(`gap-6`) |
| 历史位置：标题行→正文行 / 主文↔侧栏 | 20px / 56px |

### 5.3 色彩(source of truth：`styles/global.css` 变量 + `lib/format.ts`)

| token | 值 | 用途 |
|---|---|---|
| `--color-paper` | `#f9f7f1` | 页面底色 |
| `--color-paper-deep` | `#ecebe4` | 芯片/日历底色 |
| `--color-ink` | `#0f1217` | 标题/主文字 |
| `--color-ink-2` | `#5c6470` | 正文/次级文字 |
| `--color-ink-3` | `#8b929c` | 说明/禁用 |
| `--color-hairline` | `#e0dfda` | 发丝线/表格线 |
| `--color-accent` | `#1a57de` | 链接/当前项/高亮 |
| 分类色(工程/研究/Commit/Release) | `#6e7682 / #a684d6 / #8e96a3 / #d97aa6` | `format.ts SIGNAL_CLASSES`，kicker 色点与分布条共用 |
| 破坏性/警示 | `#cc3b33 / #e0b341` | Banner 与不兼容标记 |

### 5.4 行长与容器

| 对象 | 限制 |
|---|---|
| 页面容器 `.tp-shell` | `max-width: 2200px` + `padding-inline: clamp(20px, 2vw, 40px)` |
| 报告页布局 `.report-layout` | 左 rail 148px + gap 40px + 内容 1fr |
| 历史位置正文 | `max-width: 60em` |
| Hero 摘要 | `max-width: 48em` |
| 数据带 `.report-metrics-block` | `max-width: 820px` |

### 5.5 符号系统

- **方向箭头**：CSS 细线 chevron(`.rp-chevron`：7px 方框、1.5px 右边+下边边框、rotate 45°；
  左=135°、右=-45°、折叠开合=45°↔-135° 带 0.15s 过渡；大号 `.rp-chevron-lg` 10px/1.75px)。
  禁止文本符号 `⌄ ← →  ›` 作控件图标(链接文案中的“→”属链接语言，例外)。
- **分类色点**：7px、`border-radius: 2px`、`background: currentColor`，钉标题首行右侧。
- **导航当前项指示器**：40×2px 蓝条，锚定文字行盒下方 4px(不贴头部底边)。

### 5.6 交互约定

- 标题即链接：`color` 继承、hover 变 `--color-accent` + 1px 下划线(offset 6px)、点击开抽屉；
  抽屉为 `<dialog>` 覆盖层，ESC 关闭，不跳页。
- 可点行/卡：hover 底色 `accent 4-10%` 混合。
- 折叠摘要/分页/`<details>`：首屏最小信息量原则的实现手段。

## 6. 后端后续项(前端已用降级方案，待后端排期)

- **趋势脉络可追溯化**：`top_new_trends` / `top_continuing_trends` 现为 `list[str]` 纯文本，
  前端无法可靠挂信号链接。后端改为 `list[{text, signal_ids}]` 后，前端为每条趋势补
  “N 条信号 →”链接(跳转全部信号并筛选)。当前前端方案：卡片化提权 + 宽度收敛。
- **Δ 论点结构化**：`trend_delta` 现为含 ①②③ 的段落字符串，前端按带圈数字正则切分为列表
  (切不出则回落段落)。后端改为 `trend_points: list[str]` 后可移除正则依赖。

## 7. 防回归 checklist(改版面前逐条对照)

- [ ] 新增/修改的标题是否落在字号阶梯的既有档位上？是否大于自己的正文？
- [ ] 是否引入了单独一行的分类标签、单独一行的“查看详情”链接、或无信息的编号？
- [ ] 所有新内容左缘是否落在栏左基准线上？缩进是否有语义理由(引用块/容器内边距)？
- [ ] 垂直间距是否只用 16 / 28 / 48 三档(或说明理由)？
- [ ] 宽屏下是否产生无归属的右侧空白？(侧栏承接或多列化，二选一)
- [ ] 正文是否保持 60em 行长限制？容器是否未突破 2200px 封顶？
- [ ] 控件图标是否使用 chevron 族？是否误用文本箭头符号？
- [ ] 并行语义层是否有并行层标题？层标题右侧说明是否推至行尾？
- [ ] 首屏信息量是否仍为“决策最小集”(渐进披露未被破坏)？
